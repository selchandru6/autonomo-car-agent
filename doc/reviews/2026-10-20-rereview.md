### G4 Partially fixed: year- and trim-filtered links are still accepted
`x5_link_score` rejects `trim` by name, but `year` and `modelandtrim` are in `_BENIGN_PARAMS`. Repro:

```python
from carshop.registry.discovery import x5_link_score as s
s("https://www.bmwoflubbock.com/new-inventory/index.htm?year=2027&make=BMW&model=X5")   # 1  (should be None)
s("https://www.bmwoflubbock.com/new-inventory/index.htm?year=2027&make=BMW&model=X5&gvBodyStyle=SUV")  # 2 (should be None)
s("https://www.bmwwichitafalls.com/searchnew.aspx?Make=BMW&ModelAndTrim=X5:sDrive40i")   # 1  (should be None)
```

**Fix:**
- Treat `year` as benign only when its value is the target model year (2026) or absent. Better still, drop it from the chosen start URL, since the classifier decides the year from the VIN.
- Accept `ModelAndTrim` only when the value is exactly `X5` with no `:trim` suffix.

**Test:** the three URLs above return `None`, and `?model=X5` still returns 0.

## New findings (low)

### N1 Common add-on and fee labels are flagged `PRICE_LABEL_UNKNOWN`
“Window Tint” (Arlington), “Dealer Accessories” and “Sales Service Fee” (Autobahn) now classify as `UNCLASSIFIED`. The vehicle-only subtraction still handles them correctly, but every car at those dealers carries `PRICE_LABEL_UNKNOWN`, which hides real layout changes.

**Fix:**
- Add `tint`, `accessor`, `protection`, `package` (when paired with a dealer name) and `appearance` → ADDON.
- Add `service fee` and `dealer fee` → FEE.

**Test:** these three live labels produce no `PRICE_LABEL_UNKNOWN`.

### N2 ADR 0005 misstates who chose the price basis
[0005-price-basis.md](../adr/0005-price-basis.md) says “The owner left the choice to the implementer.” The owner hadn't decided yet; the reviewer *recommended* vehicle-only. Change the status line to “accepted pending owner confirmation”, and update it once the owner confirms.

### N3 The host crontab's 07:00 catch-up fails every day a 06:00 run succeeded
[deploy/crontab](../../deploy/crontab) line 13 runs `carshop run --trigger catchup --notify` unconditionally. When the 06:00 run exists, `RunRejected` gives a non-zero exit, and cron mails `MAILTO` daily. `entrypoint.sh` guards this correctly; the crontab doesn't.

**Fix:** have the CLI exit 0 with “scheduled run already exists” when the trigger is `catchup`, or guard the cron line.
